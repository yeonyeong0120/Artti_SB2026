## 1. 문제 정의

### 01 어떤 문제가 있는가?

2025년 기준 국내 청각장애 특수교육대상자는 2,812명이며, 이 중 약 81.5%인 2,293명이 일반학교(특수학급 + 전일제 통합학급)에 재학 중이다. 즉 대부분의 농인 학생은 청인 학생·교사와 함께 수업을 듣는 통합교육 환경에 있다. (출처: 교육부 · 국립특수교육원, 2025년 특수교육통계)

| 구분 | 특수학교 | 일반학교(통합학급) | 계 |
| --- | --- | --- | --- |
| 청각장애 학생 수 | 511명 | 2,293명 (81.5%) | 2,812명 |

그러나 교실 현장에서 실시간 수어 통역 인력이 상시 배치되는 경우는 드물고, 교사와 반 친구들은 한국수어를 이해하지 못하는 경우가 대부분이다. 이로 인해 농인 학생이 수업 중 질문·발표·토론에 참여하기 어렵고, 교사 발화를 즉시 파악하기도 쉽지 않다.

한국수어는 한국어와 어순·문법이 다른 독립 언어이며, 필담으로 청인 수준의 의미 전달이 가능한 농인은 약 12%, TV 자막을 완전히 이해할 수 있는 농인은 약 9%에 불과하다. (출처: NIA 수어영상 AI 데이터셋 설명서) 즉 수업 중 필담으로 대체하는 것도 근본 해결이 되지 못한다.

### 02 왜 이 문제가 중요한가?

수업 참여의 제약은 단순한 학습권 문제를 넘어 또래 관계 형성·자기표현 기회·학업 성취에 연쇄적으로 영향을 미친다. 2008년 장애인차별금지법이 시행되었고 통합교육 비율은 꾸준히 증가해 2025년 전체 특수교육대상자의 74.1%가 일반학교에 배치되어 있으나, 정작 수업 내 실시간 소통 보조 수단은 인력에 의존하고 있어 일상적 활용이 어렵다.

특히 수업 중 농인 학생의 질문·응답은 수어 통역 인력이 없는 한 교사에게 전달되기까지 지연·누락되는 경우가 많으며, 이는 학습 참여의 질적 격차로 이어진다.

### 03 기존 해결책의 한계는?

전문 수어 통역사 상시 배치는 비용 부담이 커 학교 단위로 보편화되기 어렵다. 원격 통역 서비스도 예약·호출 절차가 필요해 수업 중 즉시 대응에는 부적합하다.

기존 수어 인식 앱·연구는 대부분 미국수어(ASL) 기반이거나 서버 의존형 대형 모델을 전제로 하여, 교실 환경처럼 네트워크가 불안정하거나 개인정보 부담이 큰 상황에서 활용이 제한적이다. 한국수어(KSL) 기반 온디바이스 실시간 인식 앱은 상용 수준으로 존재하지 않는다.

자막 기반 대안(Google Live Caption 등)은 청인 발화를 텍스트로 보여주는 역방향 접근성 도구이며, 농인의 수어 발화를 청인에게 전달하는 도구는 사실상 공백이다.

### 04 본 시스템의 인식 범위와 한계 (v3.2 보존)

본 프로젝트는 다음의 기술적 한계를 사전에 인지하고 설계 단계에서 대응 전략을 마련한다. 약점의 은폐가 아니라, MVP 범위 설정과 후속 확장 계획의 명확성을 위함이다. (§4의 검증 Top-1 98.33%는 정면 표준 환경 기준이며, 아래 한계들이 실교실 일반화 갭으로 남는다.)

**04.1 어휘 범위 한계** — 본 시스템은 **closed-set 60-클래스 분류기** 기반으로, 학습되지 않은 어휘(예: 학교별 고유명사, 특수 단원 용어)는 인식할 수 없다. 미인식 단어는 LLM 후처리(§3·§6 참조)로 부분 보완하되, 완전한 의미 복원은 보장하지 않는다.

**04.2 데이터셋 도메인 정합성** — AI Hub 한국수어 영상 데이터셋(2020)의 원 도메인은 **길찾기·교통·주소**이므로 교실 시나리오와 부분적으로만 겹친다. 통합학급 핵심 어휘 중 일부(`질문`, `화장실`, `선생님` 등)는 데이터셋에 부재하여 후속 확장 단계에서 직접 촬영 보강이 필요하다. 다만 데이터셋의 약 65%가 도메인 중립적 일반 어휘(감정·동작·상태·신체·가족·색상·요일·숫자 등)로, MVP 범위의 교실 어휘 60개는 확보 가능하다.

**04.3 화자 분포 불일치** — 데이터셋 언어제공자는 19세 이상 농인 18명이므로, 초·중·고 학생의 신체 비례·발화 속도와는 도메인 갭이 존재한다. MVP는 fine-tuning의 일반화 능력으로 보완하되, 실서비스용 정확도 확보를 위해서는 학생 화자 직접 촬영 데이터 보강이 필요하다.

**04.4 환경 단일성** — 원본 데이터는 통제된 스튜디오 환경(블루 배경, 검정 상의, 2m 거리, A/F Off, 30 FPS)에서 촬영되어 실제 교실의 가변 배경·조명·복장과 차이가 있다. MediaPipe Holistic 키포인트 추출 단계까지는 환경 변화에 비교적 강건하나, SL-GCN 입력 분포는 학습 분포에 가까울수록 정확도가 높아진다.

## 2. 서비스 소개

SignBridge는 통합학급 수업 상황을 위한 AR 수어 통역 앱이다. 교실 내 태블릿 또는 스마트폰 카메라로 농인 학생의 수어를 실시간 인식하여, 인식된 단어 나열을 Gemini API로 자연스러운 한국어 문장으로 변환한 뒤, 교사 시야에 AR 말풍선과 음성(TTS)으로 동시 출력한다. 농인 학생은 평소대로 수어로 질문·응답·발표를 할 수 있고, 교사와 반 친구들은 별도의 수어 지식 없이도 의미를 즉시 이해할 수 있다. 수업의 흐름을 끊지 않는 실시간 소통을 목표로 한다.

### 주요 활용 시나리오 — 수업 중 질의응답

- **[상황]** 수학 시간, 교사가 칠판에 문제를 풀이하고 있다.
1. 농인 학생이 이해되지 않는 부분에 대해 손을 들고 수어로 질문한다.
2. 책상 위 태블릿이 학생의 수어를 인식해 수어 단어 나열(`[질문][이해][못함]`)을 버퍼에 쌓는다.
3. 문장 종료 지점에서 Gemini API가 "이해가 안 돼서 질문 있어요" 같은 자연스러운 한국어로 변환한다.
4. 교사의 태블릿/스마트폰 화면에 AR 말풍선이 학생 위치에 겹쳐 표시되며, 동시에 TTS로 음성 출력된다.
5. 교사는 즉시 상황을 파악하고 답변을 이어간다. 반 친구들도 화면·음성을 공유해 맥락을 놓치지 않는다.

### 타겟 사용자

- 통합학급에 재학 중인 농인 학생 (2025년 기준 약 2,293명)
- 농인 학생이 있는 학급의 청인 교사
- 같은 학급의 청인 동급생
- 특수교육지원센터 · 학교 내 특수교사(보조 운영)

### 기대 효과

- 수업 중 농인 학생의 실시간 발화 참여권 확보
- 교사가 수어를 몰라도 즉시 이해·응답 가능
- 수어 통역 인력 비상주 학교에서도 보편적 활용
- 온디바이스 추론으로 학생 영상이 외부 서버로 전송되지 않음 (개인정보 보호)

**개인정보 동의 흐름** (v3.2 보존) — 학생은 촬영 대상이므로 별도 사전 동의가 필요하다. 학교 단위 일괄 동의서 + 앱 내 "동의된 학생만 인식" 토글(§7 설정)로 처리한다.

## 3. 주요 기능

| 기능 | 설명 |
| --- | --- |
| 1. 실시간 수어 단어 인식 | 카메라 영상에서 MediaPipe Holistic으로 상반신·양손·얼굴 키포인트를 추출하고, Sentis 커스텀 ONNX 모델(SL-GCN 기반)이 슬라이딩 윈도우로 수어 단어를 분류한다. 어휘는 교실 상황 빈출 단어 60개(MVP 기준). softmax 최대 확률이 임계값(예: 0.7) 미달인 구간은 미인식 토큰 `?`으로 처리한다(상세 §6). |
| 2. 자연어 문장 생성 (Gemini) | Sentis가 순차 인식한 수어 단어 나열(예: `[질문][이해][못함]`)을 Gemini API에 전달하여 자연스러운 한국어 문장(예: "이해가 안 돼서 질문 있어요")으로 변환한다. 수어와 한국어의 통사 구조 차이를 언어모델이 보정해 교사가 즉시 이해할 수 있는 문장을 생성한다. 미인식 토큰 `?`은 임의로 추측하지 않고 "(인식 실패)"로 명시하여 LLM 환각을 통제한다(상세 §6). |
| 3. AR 말풍선 + 음성 출력 | AR Foundation이 농인 학생의 얼굴·위치를 추적하여, 변환된 문장을 월드 스페이스 3D 말풍선으로 학생 머리 위에 띄운다. 동시에 Android/iOS 네이티브 TTS로 음성 출력해 교사가 화면을 보지 않고 판서 중에도 들을 수 있도록 한다. |

### 확장 기능 (Stretch Goal)

| 기능 | 설명 |
| --- | --- |
| 대화 로그 · 수업 기록 | 수업 세션(수업 시작~종료) 단위로 질의응답을 시간순 기록한다. 진행 중에는 세션 로그로 즉시 확인하고, 종료 후에는 전체 수업 로그에서 날짜별로 조회한다. 텍스트로 저장되어 사후 복습·학습 보조 자료로 활용 가능. 사후 복습용 전체 보관·내보내기·편집은 확장 범위. |

## 4. 모델 선택 근거

### 문제 인식 — KSL 전용 즉시 사용 모델은 사실상 부재

한국수어(KSL) 전용으로 즉시 사용 가능한 사전학습 체크포인트는 현재 공개된 것이 거의 없다. KSL-Guide(FG 2021), AI Hub 한국수어 데이터셋 등은 데이터를 공개했지만 재사용 가능한 모델 가중치는 공개하지 않았다. 따라서 다음 중 하나의 전략을 선택해야 한다.

- **(A) Scratch 학습** — AI Hub KSL 데이터로 직접 학습
- **(B) Cross-lingual transfer** — 다른 언어 수어 사전학습 모델을 KSL로 fine-tuning
- **(C) 일반 동작 사전학습 + KSL fine-tuning** — Kinetics/NTU 등 일반 동작 모델을 KSL로 전이

본 프로젝트는 **(B) cross-lingual transfer**를 채택한다. 이는 OpenHands(ACL 2022), Logos(2025) 등 최근 연구에서 수어 간 전이학습이 효과적이라는 점이 검증된 표준 접근이다.

### 후보 모델 비교

| 후보 | 저장소 상태 | 사전학습 가중치 | 본 프로젝트 적합성 |
| --- | --- | --- | --- |
| OpenHands (AI4Bharat) | 유지보수 중단 (2021) | 인도 등 6개 언어 SL 사전학습 공개 | 의존성 충돌 위험, HDF5 변환 비용. 참고 문헌으로만 인용. |
| ST-GCN (원본) | 활성 | Kinetics·NTU 일반 동작 사전학습 | 수어 전용이 아님. 일반 동작 → 수어 전이 효과 제한적. |
| **SL-GCN (SAM-SLR-v2)** | **활성, 수어 전용** | **AUTSL 터키수어 사전학습 공개** | **수어 전용 graph encoder, KSL로 cross-lingual fine-tuning. 본 프로젝트 채택.** |
| LSTM + MediaPipe (scratch) | 표준 baseline | 없음 (scratch) | 가장 단순. fallback 옵션으로 보유. |

### 최종 선택 — SL-GCN (SAM-SLR-v2)

SL-GCN은 ICCV 2021 ChaLearn LAP Challenge에서 isolated SLR 분야 SOTA를 기록한 모델로, AUTSL(터키수어) 데이터로 사전학습된 가중치가 공식 공개되어 있다. 본 프로젝트는 이 가중치(`joint_epoch_226_9468.pt`, AUTSL 226클래스)를 출발점으로 AI Hub KSL 데이터셋으로 fine-tuning하여 한국수어 60단어 분류기를 구축하였다.

선택 이유:

- 수어 전용으로 설계된 graph 구조 — 일반 동작 모델 대비 수어 특화 특징 학습에 유리
- 활성 저장소이며 사전학습 가중치 · 전처리 데이터 모두 공개
- AI Hub의 OpenPose 키포인트 포맷과 호환 (137점 → 27점 인덱스 매핑으로 변환)
- 모델 크기가 모바일 온디바이스 추론에 적합 (ONNX 약 16 MB)

학습은 사전학습 가중치를 배포한 원저자의 CVPR21Chal-SLR 코드 베이스(SAM-SLR-v2와 동일한 SL-GCN 정의, fine-tuning용 config 포함)에서 수행하였다.

### 학습 결과 요약 (KSL 60단어, joint 스트림)

| 항목 | 값 |
| --- | --- |
| 사전학습 출처 | AUTSL(터키수어) 226클래스, SL-GCN joint 스트림 |
| 학습 데이터 | AI Hub 한국수어 60단어 (학습 959 / 검증 120 클립, 정면 F 각도) |
| 검증 Top-1 정확도 | 98.33% (Top-5 99.17%, Macro F1 98.22%) |
| 학습 환경 · 시간 | Google Colab Tesla T4, 80 에폭 약 22분 |
| 배포 형식 | ONNX (opset 13), 입력 (1, 3, 100, 27, 1) → 출력 (1, 60) |

> **검증 분할 및 한계 (v3.2 보존 통합)** — 화자 분할 평가 방식은 학계 표준을 준수하여 **Training batch 01~16 (16명) / Validation batch 17~18 (2명)**으로 화자 단위 분리하였다. 다만 검증셋이 클래스당 2개(총 120개)로 작고, **별도의 test셋은 없어 검증셋으로 갈음**하므로 위 수치는 정면 표준 환경 기준의 일반화 추정치다. 교실 일반화를 위해서는 향후 화자·각도·조명 다양성 확대가 필요하다.

## 6. Sentis 모델 활용 계획

| 구분 | 내용 |
| --- | --- |
| 사용할 Sentis 모델 | 커스텀 ONNX 모델 — SL-GCN 기반 KSL 분류기 |
| 선택 이유 | 한국수어(KSL) 전용 즉시 사용 가능한 사전학습 체크포인트가 부재하므로, SL-GCN(SAM-SLR-v2)의 AUTSL 사전학습 가중치를 가져와 AI Hub KSL 데이터셋으로 cross-lingual fine-tuning하였다. SL-GCN은 ICCV 2021 ChaLearn LAP isolated SLR Challenge SOTA 모델로 수어 전용 graph encoder를 갖추고 있어 KSL로의 전이가 효율적이다. 학습된 가중치를 ONNX(opset 13)로 export하여 Sentis에 탑재하며, 키포인트 기반이라 모델 크기가 작아(약 16 MB) 모바일 온디바이스 추론에 적합하다. 학생 영상이 외부 서버로 전송되지 않으므로 교실 환경 개인정보 보호에도 유리하다. |
| 입력 데이터 | MediaPipe Holistic이 카메라 프레임에서 추출한 키포인트 시퀀스. 학습 데이터는 프레임당 137점(Pose 상반신 + 양손 각 21 + 얼굴)이며, SL-GCN 입력 규약에 맞춰 수어 핵심 27점(상체 7점 + 양손 각 10점)으로 인덱스 매핑한다. 어깨 중심 기준 좌표 정규화 후 텐서로 변환한다. ONNX 입력 텐서는 (1, 3, 100, 27, 1) 형태로, 최근 100프레임 윈도우의 joint 좌표를 사용한다. 학습 단계에서는 AI Hub의 OpenPose 키포인트 JSON을 동일 포맷으로 변환하여 학습·추론 시 입력 분포를 일치시켰다. |
| 출력 결과 및 미인식 처리 (v3.2 보존) | 60개 교실 빈출 단어 클래스에 대한 softmax 확률 벡터. 처리 규칙: `max_prob ≥ 0.7` → 단어 확정, 버퍼에 push (예: `{ 단어: "이해", 신뢰도: 0.87 }`). `max_prob < 0.7` → **미인식 토큰 `?` push** (예: `{ 단어: "?", 신뢰도: 0.42 }`). 확정/미인식 모두 동일한 버퍼에 시간순으로 누적되며, 사용자(청인)는 화면 상단 인디케이터에서 실시간 인식 상태를 확인할 수 있다(녹/노/회 — §7 참조). **미인식 토큰을 버리지 않는 이유**: `?`로 명시함으로써 청인 교사가 "앞 단어 인식이 안 됐다"는 사실을 인지하고 농인 학생에게 재발화를 요청할 수 있는 단서를 제공한다. |
| Gemini 활용 (v3.2 보존 — 환각 통제) | Sentis가 확정/미인식 토큰을 버퍼에 순차 누적하고, 일정 시간(예: 1.5초) 입력이 없으면 문장 종료로 간주하여 Gemini API에 시퀀스를 전달한다. **프롬프트 핵심 규칙**: ① `?`에 해당하는 단어를 임의로 추측하지 말 것, ② `?`가 있으면 문장에서 "(인식 실패)" 또는 "[알 수 없음]"으로 명시할 것, ③ 인식된 단어만으로 의미가 통하는 최소한의 문장을 만들 것. 이러한 설계는 LLM 환각으로 인한 잘못된 의미 전달을 통제하며, 부분 인식 상황에서도 청인-농인 협력으로 소통을 이어갈 수 있게 한다. 반환된 문장은 AR 말풍선과 TTS로 동시 출력. 예: `[질문][이해][못함]` → "이해가 안 돼서 질문 있어요", `[?, 먹다, 원하다]` → "(인식 실패) 먹고 싶어요". |
| 스트림 구성 | SL-GCN은 joint / bone / joint motion / bone motion 4스트림 앙상블을 지원하나, 본 MVP에서는 joint 스트림 단독으로 학습·배포한다. joint 단독으로 검증 Top-1 98.33%를 확보하여 실용 수준에 도달했으며, 정확도 향상이 필요할 경우 나머지 스트림을 추가해 앙상블로 확장할 수 있다. |

## 7. 화면 구성 및 수업 세션

본 앱은 홈(대시보드)을 허브로 하여 수업 인식·로그·설정 화면으로 분기한다. 화면 전환 흐름은 다음과 같다.

```
스플래시 → 카메라 권한 요청 → 홈(대시보드) → [수업 시작] → 수업 인식 → (우상단 메뉴) 세션 로그 / 종료
```

홈에서는 전체 수업 로그와 설정으로 진입한다.

### 수업 세션 개념

수업 세션은 홈에서 "수업 시작"을 누른 시점부터 "종료"를 누르는 시점까지를 하나의 단위로 묶는 개념이다. 한 세션 동안 인식·변환된 발화는 진행 중에는 기기 메모리에 순차 누적되며, 종료 시 하나의 기록으로 기기에 저장된다(외부 서버 전송 없음).

이 구조에 따라 로그 화면은 두 종류로 구분된다. 수업 인식 중 우상단 메뉴로 진입하는 **세션 로그**는 현재 진행 중인 세션의 발화만 표시하고, 홈에서 진입하는 **전체 수업 로그**는 저장된 모든 세션을 날짜순으로 조회한다.

AR 카메라와 온디바이스 추론은 발열·배터리 부담이 큰 연속 작업이므로, 세션 시작 시 파이프라인을 기동하고 종료 시 정지하여 비수업 시간의 불필요한 가동을 막는다.

### 화면별 구성

| 화면 | 주요 구성 |
| --- | --- |
| 홈 (대시보드) | "수업 시작" 버튼(수업 세션 시작 및 카메라·추론 파이프라인 기동) · 전체 수업 로그 진입 · 설정 진입 · 모델 로드·카메라 권한 등 준비 상태 표시 · 최초 실행 시 사용 안내(태블릿을 학생 정면에 배치 등) |
