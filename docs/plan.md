# 1. 문제 정의

## 1.1 어떤 문제가 있는가

2025년 기준 국내 청각장애 특수교육대상자는 2,812명이며, 이 중 약 81.5%인 2,293명이 일반학교(특수학급 + 전일제 통합학급)에 재학 중이다. 즉 대부분의 농인 학생은 청인 학생·교사와 함께 수업을 듣는 통합교육 환경에 있다. (출처: 교육부 · 국립특수교육원, 2025년 특수교육통계)

| 구분 | 특수학교 | 일반학교(통합학급) | 계 |
|---|---|---|---|
| 청각장애 학생 수 | 511명 | **2,293명 (81.5%)** | **2,812명** |

그러나 교실 현장에서 실시간 수어 통역 인력이 상시 배치되는 경우는 드물고, 교사와 반 친구들은 한국수어를 이해하지 못하는 경우가 대부분이다. 농인 학생이 수업 중 질문·발표·토론에 참여하기 어렵고, 교사 발화를 즉시 파악하기도 쉽지 않다.

한국수어는 한국어와 어순·문법이 다른 독립 언어이며, 필담으로 청인 수준의 의미 전달이 가능한 농인은 약 12%, TV 자막을 완전히 이해할 수 있는 농인은 약 9%에 불과하다 (출처: NIA 수어영상 AI 데이터셋 설명서). 수업 중 필담으로 대체하는 것도 근본 해결이 되지 못한다.

## 1.2 왜 이 문제가 중요한가

수업 참여의 제약은 단순한 학습권 문제를 넘어 또래 관계 형성·자기표현 기회·학업 성취에 연쇄적으로 영향을 미친다. 2008년 장애인차별금지법이 시행되었고 통합교육 비율은 꾸준히 증가해 2025년 전체 특수교육대상자의 74.1%가 일반학교에 배치되어 있으나, 정작 수업 내 실시간 소통 보조 수단은 인력에 의존하고 있어 일상적 활용이 어렵다.

특히 수업 중 농인 학생의 질문·응답은 수어 통역 인력이 없는 한 교사에게 전달되기까지 지연·누락되는 경우가 많으며, 이는 학습 참여의 질적 격차로 이어진다.

## 1.3 기존 해결책의 한계

- **전문 수어 통역사 상시 배치**: 비용 부담이 커 학교 단위로 보편화 어려움
- **원격 통역 서비스**: 예약·호출 절차가 필요해 수업 중 즉시 대응 부적합
- **기존 수어 인식 앱·연구**: 대부분 미국수어(ASL) 기반이거나 서버 의존형 대형 모델. 교실 환경의 네트워크 불안정성·개인정보 부담과 충돌. 한국수어(KSL) 기반 온디바이스 실시간 인식 앱은 상용 수준으로 부재
- **자막 기반 대안 (Google Live Caption 등)**: 청인 발화 → 텍스트로 보여주는 역방향 접근성 도구. 농인의 수어 발화를 청인에게 전달하는 도구는 사실상 공백

## 1.4 본 시스템의 인식 범위와 한계 (v3.2 신설)

본 프로젝트는 다음의 기술적 한계를 사전에 인지하고 설계 단계에서 대응 전략을 마련한다. 약점의 은폐가 아니라, MVP 범위 설정과 후속 확장 계획의 명확성을 위함이다.

### 1.4.1 어휘 범위 한계
본 시스템은 **closed-set 60-클래스 분류기** 기반으로, 학습되지 않은 어휘(예: 학교별 고유명사, 특수 단원 용어)는 인식할 수 없다. 미인식 단어는 LLM 후처리(§3·§6 참조)로 부분 보완하되, 완전한 의미 복원은 보장하지 않는다.

### 1.4.2 데이터셋 도메인 정합성
AI Hub 한국수어 영상 데이터셋(2020)의 원 도메인은 **길찾기·교통·주소**이므로 교실 시나리오와 부분적으로만 겹친다. 통합학급 핵심 어휘 중 일부(`질문`, `화장실`, `선생님` 등)는 데이터셋에 부재하여 후속 확장 단계에서 직접 촬영 보강이 필요하다. 다만 데이터셋의 약 65%가 도메인 중립적 일반 어휘(감정·동작·상태·신체·가족·색상·요일·숫자 등)로, MVP 범위의 교실 어휘 60개는 확보 가능하다.

### 1.4.3 화자 분포 불일치
데이터셋 언어제공자는 19세 이상 농인 18명이므로, 초·중·고 학생의 신체 비례·발화 속도와는 도메인 갭이 존재한다. MVP는 fine-tuning의 일반화 능력으로 보완하되, 실서비스용 정확도 확보를 위해서는 학생 화자 직접 촬영 데이터 보강이 필요하다.

### 1.4.4 환경 단일성
원본 데이터는 통제된 스튜디오 환경(블루 배경, 검정 상의, 2m 거리, A/F Off, 30 FPS)에서 촬영되어 실제 교실의 가변 배경·조명·복장과 차이가 있다. MediaPipe Holistic 키포인트 추출 단계까지는 환경 변화에 비교적 강건하나, SL-GCN 입력 분포는 학습 분포에 가까울수록 정확도가 높아진다.

# 2. 서비스 소개

## 2.1 앱 개요
교실 내 태블릿/스마트폰 카메라로 농인 학생의 수어를 실시간 인식 → 인식 단어 시퀀스를 Gemini API로 자연스러운 한국어 문장으로 변환 → 교사 시야에 AR 말풍선 + 음성(TTS) 동시 출력. 농인 학생은 평소대로 수어로 질문·응답·발표를 하고, 교사와 반 친구들은 별도의 수어 지식 없이도 의미를 즉시 이해. 수업 흐름을 끊지 않는 실시간 소통이 목표.

## 2.2 사용자 구조 (v3.2 명시)

| 구분 | 직접 사용자 (청인) | 인식 대상 (농인 학생) |
|---|---|---|
| 디바이스 조작 | O — 앱 실행, 카메라 조준, 설정 변경 | X — 디바이스에 손대지 않음 |
| 화면 응시 | O — AR 말풍선·자막 확인 | △ — 인식 상태 인디케이터(녹/노/회)를 흘끔 보고 재발화 결정 |
| 청각 출력 듣기 | O — TTS 음성으로 농인 발화 파악 | X |
| 권한 동의 주체 | O — 앱 설치 시 카메라 권한 동의 | O — 촬영 대상으로서 별도 사전 동의 필요 |

**카메라 구도**: 후면 카메라가 기본. 청인이 농인 학생을 비추는 구도이므로 AR 말풍선 좌표계도 청인 사용자 시점 기준.

**개인정보 동의 흐름**: 학교 단위 일괄 동의서 + 앱 내 "동의된 학생만 인식" 토글(§7.3)로 처리.

## 2.3 주요 활용 시나리오 — 수업 중 질의응답 (v3.2 어휘 조정)

**[상황]** 수학 시간, 교사가 칠판에 문제를 풀이하고 있다.

1. 농인 학생이 이해되지 않는 부분에 대해 손을 들고 수어로 표현한다.
2. 책상 위 태블릿이 학생의 수어를 인식해 단어 시퀀스 `[모르다][이해]`를 버퍼에 쌓는다.
3. 문장 종료 지점에서 Gemini API가 "이해가 안 돼서 잘 모르겠어요"로 변환한다.
4. 교사의 태블릿/스마트폰 화면에 AR 말풍선이 학생 위치에 겹쳐 표시되며, 동시에 TTS로 음성 출력된다.
5. 교사는 즉시 상황을 파악하고 답변을 이어간다. 반 친구들도 화면·음성을 공유해 맥락을 놓치지 않는다.

**시연 가능한 추가 예시** (모두 데이터셋 보유 어휘 기반):
- `[피곤][오다]` → "오늘 좀 피곤해요"
- `[어렵다][모르다]` → "이거 어려워서 잘 모르겠어요"
- `[감사]` → "감사합니다"

## 2.4 타겟 사용자 및 기대 효과

**타겟**:
- 직접 사용자(앱 조작): 통합학급 청인 교사, 청인 동급생
- 인식 대상: 통합학급 농인 학생 (2025년 기준 약 2,293명)
- 운영 지원: 특수교육지원센터, 학교 내 특수교사

**기대 효과**:
- 수업 중 농인 학생의 실시간 발화 참여권 확보
- 교사가 수어를 몰라도 즉시 이해·응답 가능
- 수어 통역 인력 비상주 학교에서도 보편적 활용
- 온디바이스 추론으로 학생 영상이 외부 서버로 전송되지 않음 (개인정보 보호 — Gemini API만 네트워크 사용)

# 3. 주요 기능

## 3.1 실시간 수어 단어 인식
카메라 영상에서 **MediaPipe Holistic**으로 상반신·양손·얼굴 키포인트를 추출하고, **Sentis 커스텀 ONNX 모델(SL-GCN 기반)**이 2초 단위 슬라이딩 윈도우로 수어 단어를 분류한다. 초기 어휘는 AI Hub 데이터셋 보유 어휘 중 교실 빈출 단어 **60개** (§8.2 셔틀리스트 확정). softmax 출력의 최대 확률이 임계값(예: 0.7) 미달인 구간은 **미인식 토큰 `?`**으로 처리하여 단어 버퍼에 push한다.

## 3.2 자연어 문장 생성 (Gemini) — v3.2 보강
Sentis가 순차 인식한 단어 시퀀스(예: `[모르다][이해]` 또는 `[?, 먹다, 원하다]`)를 Gemini API에 전달하여 자연스러운 한국어 문장으로 변환한다. **프롬프트에 "`?`에 해당하는 단어를 임의로 추측하지 말고 '(인식 실패)'로 명시하라"는 규칙을 부여하여 LLM 환각 위험을 통제**한다.

**결과 예시**:
- `[모르다][이해]` → "이해가 안 돼서 잘 모르겠어요"
- `[?, 먹다, 원하다]` → "(인식 실패) 먹고 싶어요"

이는 청인 교사가 농인 학생에게 재발화를 요청할 수 있는 단서가 된다.

## 3.3 AR 말풍선 + 음성 출력
AR Foundation이 농인 학생의 얼굴·위치를 추적하여, 변환된 문장을 월드 스페이스 3D 말풍선으로 학생 머리 위에 띄운다. 동시에 Android/iOS 네이티브 TTS로 음성 출력해 교사가 화면을 보지 않고 판서 중에도 들을 수 있도록 한다. 카메라 구도는 후면 카메라 기준이며, 청인 사용자 시점에서 자연스럽게 보이도록 좌표계를 구성한다.

## 3.4 확장 기능 (Stretch Goal)

- **대화 로그 · 수업 기록**: 수업 중 발생한 질의응답을 시간순으로 기록하여 학생·학부모가 사후 복습. 텍스트 저장이라 학습 보조 자료로도 활용.
- **역방향 (교사 → 학생)**: 교사의 한국어 음성을 STT로 받아 핵심 단어를 수어 영상 클립 시퀀스로 재생(사전 녹화 영상 사전 기반). MVP 이후 개발.
- **어휘 확장 (직접 촬영)**: AI Hub 데이터셋에 부재한 통합학급 핵심 어휘(질문·화장실·선생님·숙제·발표 등) 및 학교별 특수 어휘를 직접 촬영하여 학습 데이터에 추가. 가이드라인 §3.1.6 절차를 따르며, MVP 이후 확장 단계의 핵심 과제.

# 4. 모델 선택 근거

## 4.1 문제 인식 — KSL 전용 즉시 사용 모델은 사실상 부재
한국수어(KSL) 전용으로 즉시 사용 가능한 사전학습 체크포인트는 거의 없다. KSL-Guide(FG 2021), AI Hub 한국수어 데이터셋 등은 데이터를 공개했지만 재사용 가능한 모델 가중치는 공개하지 않았다. 가능한 전략은:

- (A) **Scratch 학습** — AI Hub KSL 데이터로 직접 학습
- (B) **Cross-lingual transfer** — 다른 언어 수어 사전학습 모델을 KSL로 fine-tuning ← **본 프로젝트 채택**
- (C) **일반 동작 사전학습 + KSL fine-tuning** — Kinetics/NTU 등 일반 동작 모델을 KSL로 전이

(B)는 OpenHands(ACL 2022), Logos(2025) 등 최근 연구에서 수어 간 전이학습이 효과적이라는 점이 검증된 표준 접근이다.

## 4.2 후보 모델 비교

| 후보 | 저장소 상태 | 사전학습 가중치 | 적합성 |
|---|---|---|---|
| OpenHands (AI4Bharat) | 유지보수 중단 (2021) | 인도 등 6개 언어 SL | 의존성 충돌 위험, HDF5 변환 비용. 참고 문헌으로만 인용. |
| ST-GCN (원본) | 활성 | Kinetics·NTU 일반 동작 | 수어 전용이 아님. 전이 효과 제한적. |
| **SL-GCN (SAM-SLR-v2)** | **활성, 수어 전용** | **AUTSL 터키 수어** | **수어 전용 graph encoder. 본 프로젝트 채택.** |
| LSTM + MediaPipe (scratch) | 표준 baseline | 없음 | 가장 단순. fallback 옵션. |

## 4.3 최종 선택 — SL-GCN (SAM-SLR-v2)
ICCV 2021 ChaLearn LAP Challenge에서 isolated SLR 분야 SOTA를 기록한 모델로, AUTSL(터키 수어) 데이터로 사전학습된 가중치가 공식 공개되어 있다. 본 프로젝트는 이 가중치를 출발점으로 AI Hub KSL 데이터셋으로 fine-tuning하여 한국수어 60단어 분류기를 구축한다.

**선택 이유**:
- 수어 전용으로 설계된 graph 구조 — 일반 동작 모델 대비 수어 특화 특징 학습에 유리
- 활성 저장소이며 사전학습 가중치 · 전처리 데이터 모두 공개
- AI Hub의 OpenPose 키포인트 포맷과 호환 (인덱스 매핑만 필요)
- 모델 크기가 모바일 온디바이스 추론에 적합 (~수 MB 수준)

# 6. Sentis 모델 활용 계획

## 6.1 사용할 모델
**커스텀 ONNX — SL-GCN 기반 KSL 분류기** (YOLO/BlazePose/BlazeFace 미사용)

## 6.2 선택 이유
KSL 전용 즉시 사용 가능한 사전학습 체크포인트 부재 → SL-GCN(SAM-SLR-v2)의 AUTSL 사전학습 가중치를 가져와 AI Hub KSL 데이터셋으로 cross-lingual fine-tuning. ICCV 2021 ChaLearn LAP isolated SLR Challenge SOTA로 수어 전용 graph encoder 보유. ONNX export 후 Sentis 탑재. 키포인트 기반이라 모델 크기 작아 모바일 온디바이스 추론 적합. 학생 영상이 외부 서버로 전송되지 않아 교실 환경 개인정보 보호에 유리.

## 6.3 입력 데이터
MediaPipe Holistic이 카메라 프레임에서 추출한 키포인트 시퀀스.

- 프레임당: Pose 상반신 + 양손 각 21 + 얼굴 주요 포인트
- 30 FPS, 최근 60프레임(약 2초) 슬라이딩 윈도우
- 어깨 중심 기준 좌표 정규화 후 SL-GCN 입력 규약(노드 인덱스 매핑)에 맞춰 텐서 변환
- 학습 단계에서는 AI Hub의 OpenPose 키포인트 JSON을 동일 포맷으로 변환하여 학습·추론 시 입력 분포 일치

## 6.4 출력 결과 및 미인식 처리 (v3.2 보강)

60개 교실 빈출 단어 클래스에 대한 softmax 확률 벡터.

**처리 규칙**:
- `max_prob ≥ 0.7` → 단어 확정, 버퍼에 push. 예: `{ 단어: "이해", 신뢰도: 0.87 }`
- `max_prob < 0.7` → **미인식 토큰 `?` push**. 예: `{ 단어: "?", 신뢰도: 0.42 }`

확정/미인식 모두 동일한 버퍼에 시간순으로 누적되며, 사용자(청인)는 화면 상단 인디케이터에서 실시간 인식 상태를 확인할 수 있다(녹/노/회 — §7.1 참조).

**미인식 토큰을 버리지 않는 이유**: `?`로 명시함으로써 청인 교사가 "앞 단어 인식이 안 됐다"는 사실을 인지하고 농인 학생에게 재발화를 요청할 수 있는 단서를 제공한다.

## 6.5 Gemini 활용 (v3.2 보강 — 환각 통제)

Sentis가 확정/미인식 토큰을 버퍼에 순차 누적하고, 일정 시간(예: 1.5초) 입력이 없으면 문장 종료로 간주하여 Gemini API에 시퀀스를 전달한다.

**프롬프트 핵심 규칙**:

```
다음 수어 단어 시퀀스를 수업 상황에 맞는 자연스러운 한국어 문장으로 변환하세요.
'?'는 인식에 실패한 단어를 의미합니다.

규칙:
1. '?'에 해당하는 단어를 임의로 추측하지 마세요.
2. '?'가 있다면 문장에서 "(인식 실패)" 또는 "[알 수 없음]"으로 명시하세요.
3. 인식된 단어만으로 의미가 통하는 최소한의 문장을 만드세요.
```

**결과 예시**:
- `[모르다][이해]` → "이해가 안 돼서 잘 모르겠어요"
- `[?, 먹다, 원하다]` → "(인식 실패) 먹고 싶어요"
- `[어렵다][모르다]` → "이거 어려워서 잘 모르겠어요"

이러한 프롬프트 설계는 **LLM 환각으로 인한 잘못된 의미 전달을 통제**하며, 부분 인식 상황에서도 청인-농인 협력으로 소통을 이어갈 수 있도록 한다. 반환된 문장은 AR 말풍선과 TTS로 동시 출력.

# 7. AR 화면 구성

## 7.1 화면 1 — 수업 인식 (메인)

- AR Foundation 카메라 피드 전면 표시 (후면 카메라 기본)
- **상단 인식 상태 인디케이터 (v3.2 신설)**:
  - 🟢 **녹색**: 단어 확정 인식 (신뢰도 ≥ 임계값)
  - 🟡 **노란색**: 미인식 토큰 `?` (키포인트 감지되나 신뢰도 미달)
  - ⚪ **회색**: 수어 동작 감지 중 (분류 결과 없음)
- 누적 단어 버퍼 표시 (최근 시퀀스)
- 학생 머리 위 월드 스페이스 3D 말풍선
- 하단: 최근 변환 문장 자막 (Live Caption 형태)
- 디버그 모드 시 키포인트 오버레이

## 7.2 화면 2 — 수업 로그

- 수업 시간별 발화 로그 (시간순)
- 각 항목: 원본 수어 단어 나열 + Gemini 변환 결과
- 미인식 토큰 포함 항목은 별도 표시 (`?` 아이콘)
- 항목별 TTS 재생 / 편집 / 삭제
- 학습 복습용 내보내기 (텍스트)
- 오인식 피드백 버튼

## 7.3 화면 3 — 설정

- 인식 신뢰도 임계값 조절 (0.5~0.9 슬라이더)
- TTS 음성 / 속도 / 볼륨
- 지원 단어 목록 확인 (교실 어휘 60개)
- Gemini 문장 변환 on / off
- Gemini 환각 통제 모드 (엄격/완화)
- 데이터 외부 전송 여부 표시 (모델 추론은 온디바이스, Gemini만 네트워크 사용)
- **"동의된 학생만 인식" 토글 (v3.2 신설)**
